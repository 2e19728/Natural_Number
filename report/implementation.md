# natural AVX-512 变体 — 实现与实验（技术正文）

> 读者假定：了解大整数乘法与 NTT 的基本概念，不需要预先了解本项目的代码。
> 本文自包含：与标量树的全部差异、每个内核的构造、验证手段、全部实测数据、分析，
> 以及每条数据的出处。标量引擎本身的完整技术正文在标量树的
> `report/implementation.md`，本文不重复它的推导，只讲这一版**做了什么、值多少、边界在哪**。
>
> **测量条件（全部数据统一）**：同一台笔记本（i7-11800H，Tiger Lake-H，ZMM 实测频率
> 4.38 – 4.59 GHz；L1d 48 KiB / L2 1.25 MiB / L3 24 MiB，WSL2 内核 6.6.87，GCC 13.3.0），
> `taskset` 绑定同一物理核，**插电**状态（电池状态只有 2.6 – 2.9 GHz，不作为数据）。
> 两个引擎在**同一进程内逐轮交替**测量，取多轮最小值。噪声标尺：同一份代码对同一份代码的
> 对照（null）比值为 **0.998 – 1.007**。
>
> **基线**：标量树 `natural-lib` 的同名库（两者除本文 §1 列出的差异外逐字节相同），以及
> **GNU MP 6.3.0**（`-march=native -O3 -mtune=native`，与我们在同一进程内交错测量）。

## 0. 摘要

把 NTT 变换的全部调度通过程改用 AVX-512 IFMA 的 zmm 内核（一次 8 个 64 位字），
其余一切保持不变。结果：

- 相对标量版（896 … 4 194 304 字 = 2^9.8…2^22 字，14 个尺寸几何平均）：
  **乘 1.70 – 1.71 倍，平方 1.66 – 1.69 倍**；逐步 A/B 为
  1.52× → 1.57× → 1.65× → 1.70×（§7.1）。
- 相对 GNU MP 6.3.0（2^22 字 = 4 194 304 字）：**乘 2.45 – 2.56 倍，平方 2.34 – 2.39 倍**；
  标量版在同一处是 1.46 / 1.47 倍，即增益全部来自变换内核（§7.2）。
- 六个内核（三个 pass × 正逆向）与标量内核**逐位相同**：按 pass、按尺寸、按 chunk 偏移、
  按三个模数逐点比对；另有独立差分探针 95172 例 0 失败（§5）。
- 剩余阶段全部经"空心孪生 + 原型"量化后**主动放弃**：`intt_shr()` 0.1 – 0.4%、
  `load()/save()` 0.1 – 0.3%、`nat_asmNttMul` 需换数据表示、`nat_asmCRT()` 草稿实测
  八宽后算术只快 1.3 – 1.4 倍、整体反而慢 1.5 倍（§8）。

**结论**：这是"换内核"而非"改算法"的一版，增益直接来自每条指令的宽度（8 字）与
S56（IFMA 形式的 Shoup，免掉 64×64→128 的全宽模拟）；其余阶段的余量都在 1% 以内或为负，
变换本身（约占一次乘法 88% 的时间）已经向量化完毕。

## 2. 内核设计

### 2.1 4D 宏块、zmm 映射与游标约定

标量合并内核把 4D 宏块的四分之一（quarter）当作"一段 D 个元素"，逐元素循环：

```
pa = Begin, pb = Begin + D
a = pa[k]  b = pb[k]  c = pb[D+k]  d = pb[2D+k],  k = 0..D-1
forward: 外层（距离 2D，w 在 (b,d)/(a,c)）→ 内层（距离 D，w2 在 (a1,b1)、w3 在 (c1,d1)）
inverse: 内层（距离 D）→ 外层（距离 2D，w 在 (a1,c1)/(b1,d1)）
```

zmm 内核保持**同样的两层、同样的旋转因子游标**，只把"quarter 的 D 个元素"换成
**一个 zmm**（`STEP = 64` 字节，即 8 个元素一组），因此要求 `D >= 8`。
旋转因子仍按块广播（标量内核在一个块内也是同一个值）：`RootO` 每块前进 16 字节
`(w, w')`，`RootI` 每块 32 字节 `(w2, w2')`、`(w3, w3')` —— 与标量内核完全一致，
这是两个实现能逐位对齐的原因之一。

radix-2 单层内核同理：`N >= 8`，一个 zmm 管 2N 块的一半。
**注意参数个数不同**：radix-4 六个参数（`End` 在 `r9`），radix-2 五个（`End` 在 `r8`、
`Root` 在 `rcx`）——与标量内核的分法一致，写错会静默越界，所以逐 `D`/逐 `N` 的恒等测试
是唯一的保险。

### 2.2 S56：IFMA 形式的 Shoup

模乘 `v·w mod m` 用 Shoup：预存倒数 `w'`，运行时先估商 `q ≈ v·w'`，再用
`lo(v·w) − q·m` 得到 `[0, m)` 的结果（至多一次条件 `+m`）。标量版是 3 条乘法
（`mul` 取高、`imul` 取低、`imul` 乘模数）。

zmm 版面对的问题是**没有 64×64→128 的向量乘法**。`S56` 的做法是：
用 IFMA 的 52 位字段拼出估商所需的高位，再用模数的特殊形状
`m = a·2^56 + 1`（a = 27 / 58 / 87）把 `q·m` 的修正项化为一次移位加一个小常数乘法：

```
vhi  = v >> 52
acc2 = madd52hi(v, WP) + madd52lo(v, WPHI) + madd52lo(WP, vhi)       # 估商 q
acc3 = mul_epu32(vhi, WPHI) + madd52hi(v, WPHI) + madd52hi(WP, vhi)
acc2 >>= 12
acc3 += madd52lo(acc2, P30)          # P30 = ((m-1)>>56)<<16 = a<<16
acc3 <<= 40
acc2 += acc3                          # acc2 ≈ lo64(q·m)
z    = vpmullq(v, W) - acc2           # lo64(v·w) - lo64(q·m)
if (z 有符号为负) z += m              # 与标量同一判据（DST >= 2^63 视为负）
```

于是每个模乘是**一次 8 车道**的 IFMA/移位序列，没有任何一次 64×64→128 的全宽模拟，
也不需要 `mulx`。`RED`（`X >= m ? X − m : X`）同样是向量比较 + 掩码减法。
两个宏都以寄存器前缀为参数（`S56 zmm, ...` / `RED zmm, ...`），模数常量常驻
`zmm28`（m）、`zmm29`（符号位 `0x8000…`）、`zmm30`（`a<<16`），`k1`/`k2` 归它们使用。

该序列与项目里已单独验证过的实验内核 `verify/experiments/butterfly_r4_ifma.s` 同源；
在 NTT 语境下它与标量三乘法 Shoup 的结果**逐位相同**（§5.1 是全 `D`/全 `N` 的穷举证据）。

### 2.3 旋转因子构造

内层需要"每对元素复制两次"的交错模式
`[w2_0 ×2, w3_0 ×2, w2_1 ×2, w3_1 ×2]`，外层需要"每块一个"的
`[w0 ×4, w1 ×4]`。两者的构造都直接吃根表：

- 内层：**一次 64 字节 load**（`vmovdqu64`——根表游标是 qword 粒度、不保证 64 字节对齐，
  这一点用 `vmovdqa64` 会在非零 base 的 chunk 上直接段错误）+ 两条**寄存器** `vpshufd`
  （`0x44` 取 `w`，`0xee` 取 `w'`），再加一条 `vpsrlq` 得到 IFMA 需要的 `w'>>52`。
- 外层：**四条 `vpbroadcastq`**——先把高块的 `w` 广播满 8 道，再用 `k4 = 0x0f`
  合并掩码把低块的 `w` 写进低四道；`w'` 同样两条。掩码在循环外设一次。

早期版本用 `vpshufd 0x44` + `vshufi64x2 0x50` 构造外层向量：指令数相同，但要读进本次用不到
的 32 字节，且多一次跨 128 位 lane 的 shuffle。改成广播形式后，隔离测量里正向
v/s 由 0.66…0.72 变为 0.62…0.72。

### 2.4 D = 2 尾巴：三次重排

`D = 2` 时一个 4D 块只有 8 个元素，**无法给每个 quarter 一个 zmm**。调度因此把最细一层的
固定距离-2 对（层 2 与层 1）剥成 `lv.tail`，交给专用内核：**16 个元素（两个 4D 块）一次迭代**，
核心是"重排三次"，让每次蝶形的伙伴落进同一个 lane：

```
正向
  gather : [a0 b0 a1 b1] × [c0 d0 c1 d1]        i0 / i1
  outer  : 距离 2D 的竖直蝶形，乘在 [c,d] 一侧
  regroup: [b0 d0 b1 d1] × [a0 c0 a1 c1]        i2 / i3
  inner  : 距离 D 的竖直蝶形，乘在 [b,d] 一侧
  restore: 每个块的两个 quarter 交错回内存序      i4 / i5

逆向（层序相反，所以"gather"与"regroup"的角色对调）
  gather : [a c ...] × [b d ...]                iA / iB
  inner  : 距离 D 的竖直蝶形
  regroup: [a1 b1 ...] × [c1 d1 ...]            i3 / i2
  outer  : 距离 2D 的竖直蝶形
  restore: 交错回内存序                          i0 / i1
```

- 每个方向都是 **2 次 S56 + 2 次 RED、6 条 `vpermt2q`、零掩码寄存器**——与正向同形。
- 两个方向共用同一批索引向量与同一套旋转因子构造（外层每块一次广播、内层 2-lane 交错），
  因为 gather 之后距离-D 对落在与正向 regroup 相同的位置。
- 尾巴内核要求 `span` 是 16 的倍数；调度保证最细分块 `>= 2^4`，所以恒成立。

**这里踩过一个值得记录的坑。** 逆向最初图省事，用一条 `vshufi64x2 0xb1` 把距离-2D 的伙伴
在 lane 内对折过来。代价是外层必须对 a/c 与 b/d 各跑一遍，于是 16 个元素要
**3 次 S56 + 3 次 RED**（正向 2 + 2），而且 S56 参数的符号只在掩码选中的槽位正确。
改回三段重排后外层恢复为"两条向量一次竖直蝶形"，**平方的几何平均由 0.609 降到 0.592
（约 3%）**，正向的隔离比值也与之持平（正向 1.4 – 1.6×，逆向 1.39 – 1.66×）。

## 3. 调度改动：tail 剥离

标量树里最细一层可以包含 `(2,1)` 对；本树把它剥离，理由与不变式：

| level 状态 | 合并层范围 | 未配对的层 | tail |
|---|---|---|---|
| `k` 偶 | `3 .. k-2` | 无 | `(2,1)` @ `D = 2` |
| `k` 奇 | `3 .. k-2` | 层 3 @ `D = 8` | `(2,1)` @ `D = 2` |

- 合并层范围因此从层 3 起，`D = 4` 永不出现，所有合并 pass 满足 `D >= 8`；
- 未配对层从"层 1"上移到"距离-8 的层 3"，在正向放最后、逆向放最前（两个方向的
  最小距离端）；
- 分块下限由 2 提到 `k >= 4 ? 4 : 2`（最细层要容下 tail 的 16 元素一趟和距离-8 层）；
- 层运行器的空判断改为 `if (lv.hi < lv.lo && !lv.tail) return;`（合并层可以为空，
  但 tail 仍要跑）。
- 该不变式由 `t_sched_plan` 逐 `k = 4..24` 检查（tail 只属于最细层、从层 3 起、
  层与 tail 恰好铺满 `1..k-2`）。

## 4. 运行时分派与回退

```cpp
inline bool ntt_zmm_cpu_ok() {           // 启动时问一次 CPU
    return __builtin_cpu_supports("avx512f") && ... && __builtin_cpu_supports("avx512ifma");
}
inline bool ntt_zmm_enable = ntt_zmm_cpu_ok();
```

- 分派点在层运行器里：`D >= 8` / `N >= 8` 走 zmm，否则走标量；tail 走 d2 内核。
- 没有 AVX-512 的机器**静默走标量路径**（结果逐位相同），不会执行非法指令；
  显式改写 `ntt_zmm_enable` 可以强制任一实现，A/B 就靠它。
- 编译目标仍是 `-march=x86-64-v3`（本树不强制 AVX-512 编译期开关），内核只在实际检测
  通过后到达。

## 5. 验证

### 5.1 逐内核、逐形状、逐偏移，与标量内核逐位相同

`t_zmm_kernels` 对每个实现单独驱动一遍：

- 合并 radix-4：`D = 8 .. 2^(scale-2)` 的全部取值；
- 单层 radix-2：`N = 8 .. 2^(scale-1)` 的全部取值；
- 两个方向、三个模数；
- `D = 2` tail：chunk 尺寸 `T = 4..9` × **每个偏移**（覆盖 16 元素迭代的块对齐）。

每一项都是与标量内核输出 `memcmp` 全等（不是误差比较）。

**独立差分探针**（不依赖套件代码）：正向与逆向分别对拍，尺寸 2^12 … 2^16、
每个 chunk 尺寸 `T = 4 .. scale-1`、每个偏移、三个模数，合计 **95172 例，0 失败**。
（注意：探针必须喂 `[0, m)` 的新鲜数据；用正向输出再去跑逆向会把惰性范围 `[0, 2m)`
当输入，结论无效——这是调试过程中真实踩过的坑。）

**变异检查**（对套件做过、未提交）：把正向 zmm 内核的一个内部旋转因子改坏，会在全部 12 个
`D` 的逐内核检查、7 个尺寸的引擎 A/B 和基例 oracle 上同时失败；关掉 tail 会让
`k = 4..24` 的规划检查失败；tail 游标写错则由 tail 自己的偏移循环与基例 oracle 捕获。

### 5.2 端到端开/关一致

`t_zmm_paths` 对 896 … 70000 字的一组尺寸，分别在 `ntt_zmm_enable` 开与关下算乘积与平方，
要求结果完全相同——覆盖非零 base 的 chunk、层行走与标量回退路径。

### 5.3 套件计数

| 构建 | 结果 |
|---|---|
| ISA 可用（正常构建） | **3857 项，0 失败** |
| `ntt_zmm_cpu_ok()` 强制为 false | **3781 项，0 失败**（76 项 zmm 专项检查自行跳过，标量路径全过） |

## 6. 实验方法

1. **同一进程、逐轮交替**：标量与 AVX 两个二进制（或自然引擎与 GMP 两个引擎）在同一轮内
   先后测量、下一轮交换顺序，每尺寸取多轮最小值。历史教训：早期"一个连测 N 次再换另一个"
   的做法在重复轮之间差异达 10.7%，交替 + 取最小后降到 1 – 3%。
2. **噪声标尺**：另跑一个"同一份代码对同一份代码"的 null 二进制，走同样的流程；
   本报告引用的 null 比值为 0.998 – 1.007（单尺寸最坏到 ±3%，故结论只采信几何均值）。
3. **插电 + 锁核**：`taskset -c 3`，AC 供电（`/sys/class/power_supply/AC*/online == 1`）。
4. **尺寸集合**：A/B 为 896、1024、2048 … 4 194 304 字（14 个，每尺寸 200 ms 预算，
   5 轮轮转）；GMP 对比为 2^16 … 2^22 字。
5. **端到端"引擎"对照**：A/B 二进制同时构建自两棵树，都编 `perf_scalar_ab.cpp`，
   链接各自的目标文件；AVX 侧额外链入 `mul_ntt_avx512.s`。

## 7. 结果

### 7.1 逐步 A/B（相对标量库的几何均值，乘 / 平方）

| 加的东西 | 14 尺寸几何均值 | 折算倍数 |
|---|---|---|
| 只有合并 radix-4 内核 | 0.656 / 0.659 | 1.52× |
| + 单层 radix-2 内核 | 0.636 / 0.639 | 1.57× |
| + tail（正向） | 0.604 / 0.616 | 1.65× / 1.62× |
| + tail（逆向，三段重排） | **0.584 – 0.589 / 0.592 – 0.604** | **1.70 – 1.71× / 1.66 – 1.69×** |

null 对照 0.998 / 1.002 / 1.007（三次运行），因此每一步都超出噪声。最后一行跨两次完整
A/B 运行给出区间；两次运行的 2^22 行分别是 0.599 / 0.617 与 0.609 / 0.620（乘 / 平方），
差在噪声范围内。

### 7.2 与 GNU MP 6.3.0

| 2^22 字（4 194 304 字） | 乘 | 平方 |
|---|---|---|
| 本变体 | **2.45 – 2.56×** | **2.34 – 2.39×** |
| 标量版（同场次） | 1.46× | 1.47× |
| 2^16 … 2^22 全区间（本变体） | 1.8 – 2.5× | 1.7 – 2.4× |

所有行都与 GMP 结果**逐字比对**。GMP 的基线不是稻草人：对 6.3.0 自带的 22 张 x86-64
参数表做过成对 A/B，它自选的表在 10.5M – 29.4M 字区间是**对它有利**的那张。

### 7.3 尾巴内核的隔离测量

同一进程、同一 chunk 集合、5 轮取最小（`perf_tail.cpp`，scale 22）：

| | v/s = 向量 / 标量 | 折算 |
|---|---|---|
| 正向 d2 | 0.63 … 0.72 | 1.4 – 1.6× |
| 逆向 d2 | 0.60 … 0.72 | 1.39 – 1.66× |

对 `T = 4 … 21`（即最小到最大 chunk）全程成立，不随尺寸衰减；两个方向现在成本相同
（都是 2 次 S56 + 2 次 RED、6 条重排）。

### 7.4 阶段占比与归因（标量构建的测量，用于定位）

在标量构建上做的阶段分解（2^22 字）：**ntt 57%、intt 31%、NttMul 4.8%、load 3.5%、
save 3.4%**（2^16 字：55 / 30 / 6.4 / 3.2 / 4.8%）；内核给出 **ntt 1.82×、intt 1.69×**，
其余三项 1.00×。该分解早于 tail 的落地，但足以说明：变换约占 88%，是唯一有量的阶段。

空心孪生（同地址流、删算术）在 2^22 / 2^16 字下的 hollow/real：
`load()` 0.97 / 0.90（**访存受限**）、`intt_shr()` 0.65 / 0.28、`nat_asmCRT()` 0.26 / 0.13。
前者的结论是"不要动"，后两者看起来有余量——但它们分别在 §8.1 与 §8.4 被实测否掉。

## 8. 量过并放弃的四个方向

### 8.1 `intt_shr()`：能做、但太小

它是融合了"最后一层逆变换 + 右移归一化"的标量阶段（编译器不向量化：64 位乘法在
`-march=x86-64-v3` 下不会被自动向量化，反汇编里是 `imul`/`sarx`/`cmov`）。
写了一个 zmm 原型：修正项 `(h-1) & ~u` 乘**常数** `m >> s`（一条 `vpmullq`，低半部精确）、
移位用 `vpsraq`，逐位相同。隔离测量：命中缓存时（2^16 – 2^20 字）**1.6 – 1.7×**，
但到 2^22 字该阶段已受带宽限制，只剩约 **9%**。而该阶段最多占一次乘法的 **≤1.3%**，
端到端 **0.1 – 0.4%**，在噪声里。⇒ 保持标量，测量留在 `docs/avx512.md`。

### 8.2 `load()` / `save()`

两者都是"活值 × 常数"（barrett 的 mu、CRT 的常数），原理上可向量化；但空心孪生显示
`load()` 只比纯拷贝慢 3 – 10%（hollow/real 0.90 – 0.97），即**访存受限**，
天花板 0.1 – 0.3%。⇒ 不动。

### 8.3 `nat_asmNttMul`（逐点乘）

中间那一遍是"活值 × 活值"：没有预存的倒数可以 Shoup，Barrett/Montgomery 也绕不开真正的
128 位乘积。唯一出路是改用 2×52 位表示以借 IFMA，但那会让（本就访存受限的）访存翻倍。
⇒ 除非换数据表示，否则保持标量。

### 8.4 `nat_asmCRT()`：写了草稿，实测后放弃

**动机**：CRT 合并每条系数 11 条乘法，**每一条都有一个常数操作数**（模数、倒数、Shoup 乘子、
`m0·m2` 的两个半部），所以理论上全部可 IFMA 化；空心孪生给的算术上限是 2.5 – 3.7%。

**草稿**（`perf-avx/crt_vec.cpp`，intrinsics）：把每条系数的算术 8 车道化，
构造与标量完全一致（S56 用于两处"乘倒数再取模"，#4/#10/#11 用
`m0 = 27·2^56+1`、`K = 2349·2^112 + 114·2^56 + 1` 的小常数分解），
进位链暂时留标量。**结果逐位正确**（2^12 … 2^20，含 `Size % 8` 尾块）。实测（2^20 系数）：

| | 时间 | 相对标量 |
|---|---|---|
| 标量 `nat_asmCRT` | 4.11 ms | 1.00 |
| 草稿：八宽算术（不含进位） | 3.16 ms | 0.77（只快 1.3×） |
| 草稿：整内核（向量算术 + 标量进位） | 6.06 ms | 1.47（**反而慢**） |

两条原因：IFMA 序列与标量一样挤在乘法端口上，"算术免费"的 4 – 8× 拿不到；而"3 字存回 +
标量进位链"的代价超过乘法省下的，所以进位也必须向量化（移位列和 + 并行前缀）才可能回本。
两件事加起来，端到端约 1%。⇒ 不写。

**一个不显然的发现（值得留档）**：标量里 `(hi(w2·CM1) + 2)·m1` 那一步需要**精确**的
`hi64(w2·CM1)`。S56 内部的 `ACC2 >> 12` 只是**商估计**（52 位字段混合了不同 bit-scale），
拿它当 q 会让 `e` 平移 m1 的倍数——余数不变，但把 `e` 推出 S56 的有效区间，约化随即出错。
草稿的第一版就是全错，单元自测（s56 / 小常数乘 / 精确 hi64 分别对拍）才定位到这一点。

## 9. 已知边界与后续

- **硬件依赖**：只有检测到 AVX-512 F/BW/DQ/VL/IFMA 才走向量路径；否则静默回退标量，
  结果逐位相同。这既是边界也是这一版的性质：加速完全来自指令宽度。
- **尾部假设**：尾部内核要求 `span` 是 16 的倍数（调度保证）。若将来调度改动，
  需要重新确认或给尾块加掩码收尾。
- **大尺寸数据缺口**：本变体的 GMP 对比只测到 2^22 字；标量树的 `results.md` 覆盖到 2^26。
  2^23 – 2^26 段（访存更受限）本变体的领先幅度**尚未测量**。
- **两条真正的后续路线**（都属"换东西"而非"优化"）：2×52 位表示（可向量化逐点乘，
  代价是访存翻倍，需先算清账）；多线程。
- 可选的工程性收尾：把 `mul_ntt.s` 的 CRT load 折叠与标量树对齐（§1 的漂移）。
