# natural AVX-512 变体 — 阶段性汇报

> 这份说明我们做了什么、结论是什么。尽量不用专业术语；必须用的词都在第一次出现时解释。
> 所有性能数字都在同一台笔记本、**插电**、同一个 CPU 核上测的，两个引擎在同一进程内
> **逐轮交替**测量（见第六节）。标量版本身的完整汇报在标量树的 `report/` 里；本文只讲
> AVX-512 这一版**多做了什么、值多少**。

---

## 一、结论

标量版的大数乘法引擎已经能和 GNU MP（GMP，大数运算的事实标准）打得有来有回。这一版做的是
**把引擎的核心——变换——改用 AVX-512 的 512 位向量指令**，一条指令同时算 8 个数据点。

| | |
|---|---|
| 相对**标量版**（14 个尺寸几何平均，896 … 4 194 304 字） | 乘 **1.70 – 1.71 倍**，平方 **1.66 – 1.69 倍** |
| 相对 **GMP**（2²² = 419 万字） | 乘 **2.45 – 2.56 倍**，平方 **2.34 – 2.39 倍** |
| 标量版在同一处的成绩 | 1.46 / 1.47 倍 |
| 与标量版的结果 | **逐位相同**（不是"误差之内"，是每个尺寸逐字比对全等） |
| 没有 AVX-512 的机器 | 自动走标量路径，结果逐位相同，不报错 |

**提升全部来自变换内核**：GMP 对比里，标量版是 1.46 倍、这一版是 2.45 倍，中间这段就是
zmm 内核省出来的。变换占一次乘法约 88% 的时间（见第五节），也正是唯一值得动的地方。

**改了什么？** 只有内核 + 调度里一处必要的调整 + 运行时 CPU 检测。`nat_asmNttMul`、CRT、
收尾、基例、平方路径等**全部与标量版逐字节相同**（第五节列了清单）。

## 二、为什么能快：一条指令干 8 个点的活

### 2.1 两种做法的"宽度"不同

变换里的基本运算叫**蝶形**：把两个数据点配成一对，算"和"与"差（乘一个固定系数）"。
标量内核一个点一个点地做；这一版把数据**按 8 个一组排进 512 位寄存器**，一条指令处理 8 个。

标量内核一次处理一个 4D 块（"宏块"）时，四个"四分之一块"（quarter，各 D 个元素）分别放在
普通寄存器里，逐元素循环。zmm 内核的做法是：**每个 quarter 装进一个 zmm**，于是 D 个元素
一次算完。代价是要求 `D >= 8`——这正是后面要讲"尾巴"的原因。

### 2.2 难点：硬件没有"64 位 × 64 位 → 128 位"的向量指令

模乘（带取模的乘法）需要两个 64 位数相乘得到 128 位结果。标量有硬件指令；**向量没有**，
硬凑一次要十几条指令，反而更慢。

这一版的解法用了两个现成条件：

- CPU 有 **IFMA**（52 位乘法累加指令）：可以把 64 位拆成 52+12 位，用几条 IFMA 拼出需要的
  高位部分；
- 我们选的三个质数长得特殊：`m = 27 / 58 / 87 · 2⁵⁶ + 1`。所以"商的修正项"可以简化成一次
  移位加一个小常数乘法，不用真的去乘那个大质数。

两者合起来就是项目里的 **S56** 序列。它把"标量要 3 条乘法"的模乘，变成 8 车道并行的
一组 IFMA/移位——**没有一次 64×64→128 的全宽模拟**。这是整件事能成立的关键。

### 2.3 为什么不去动别的阶段

我们做过一类"**空心孪生**"实验：同一条内核，**访存动作一模一样**（读哪些地址、写哪些地址
相同），只把算术删掉。它的耗时就是"这套访存模式下任何实现的下限"，反过来就是"算术全免费时
能快到多少"。

结论：**收尾（load/save）已经是访存受限**（在纯拷贝的 3 – 10% 以内），再优化也没空间；
逐点乘（NttMul）需要"活值 × 活值"，没有预先算好的倒数可用，除非换数据表示（见第七节）。
**能省的地方只有变换本身。**

## 三、三个内核分别在做什么（大白话）

| 内核 | 干什么 | 难点 |
|---|---|---|
| `..._zmm_radix4`（正/逆） | 把两层变换合起来做一遍，一个 zmm 管一个 quarter | 要把"哪条 lane 用哪个旋转因子"对齐，再用 S56 |
| `..._zmm_radix2`（正/逆） | 调度里剩下的一层单独跑 | 同上，简单一些 |
| `..._zmm_radix4_d2`（正/逆） | 最细一层的固定 (2,1) 对（"尾巴"） | 见下 |

**"尾巴"为什么特殊。** 最细一层要处理距离 2 和距离 1 这两层，而这时一个 4D 块只有 8 个
元素——**放不下"一个 quarter 一个 zmm"**。所以调度把这一对（固定叫 (2,1) 对）单独剥出来，
交给专门的小内核；这样合并层里 `D >= 8` 恒成立，`D = 4` 那种尴尬尺寸根本不会出现。

这个小内核的做法是"**重排三次**"：用 `vpermt2q`（按索引重排 lane）把 16 个元素换个摆法，
让每次蝶形的两个伙伴落进同一个 lane，做完再排回内存顺序。正向是"先外层后内层"，逆向是
"先内层后外层"，所以逆向的三次重排顺序正好是正向的镜像。

**这里有一个我自己踩过的坑，值得记下来。** 逆向我一开始图省事，用了一条"在 lane 内部把
伙伴对折过来"的指令（`vshufi64x2`），结果外层蝶形不得不跑**两遍**（一遍管 a/c，一遍管
b/d），于是 16 个元素要 **3 次模乘 + 3 次取模**，而正向只要 2 次 + 2 次。改成和正向一样的
三段重排后，外层重新变回"两条向量做一次竖直蝶形"，**平方一项就快了 3%**（0.609 → 0.592）。
教训：省一条重排指令的代价，是算术多做一半。

## 四、做出来的提升，是一步步量出来的

同一套 A/B，每一步只加一件事：

| 加的东西 | 乘（相对标量版） | 平方 |
|---|---|---|
| 只有 radix-4 内核 | 0.656 / 0.659（1.52 倍） | — |
| + 单独的 radix-2 层 | 0.636 / 0.639（1.57 倍） | — |
| + 尾巴（正向） | 0.604 / 0.616（1.65 / 1.62 倍） | |
| + 尾巴（逆向，三段重排） | **0.584 – 0.589 / 0.592 – 0.604（1.70 – 1.71 / 1.66 – 1.69 倍）** | |

每一步的收益都有独立的隔离测量佐证：尾巴内核单独测，正向是标量版的 1.4 – 1.6 倍，
逆向是 1.39 – 1.66 倍（都从 chunk 尺寸 T=4 到 T=21 全程成立，不随尺寸衰减）。

## 五、改了什么，没改什么

**改了三处**：

1. 新增 `src/mul_ntt_avx512.s`：六个 zmm 内核（三个 pass × 正逆向）。
2. `include/natural/ntt_workspace.h`：内核声明、运行时 CPU 检测与分派，以及**最细一层剥离
   尾巴**这一步调度调整（因为向量内核要 `D >= 8`）。
3. 因此调度里最细一层的分块下限从 2 提到 4（要容得下尾巴的 16 元素一趟）。

**没改的**（与标量版逐字节相同）：逐点乘 `nat_asmNttMul`、中国剩余定理合并 `nat_asmCRT`、
收尾 `load()` / `save()`、最后一层加右移 `intt_shr()`、基例与 Toom-22、平方专用路径、
除法、接口。

**四个"量过之后主动放弃"的**（都在 `docs/avx512.md` 里有数据）：

| 想优化的 | 为什么放弃 |
|---|---|
| `intt_shr()`（收尾的最后一层 + 右移） | 能向量化、逐位相同，缓存内快 1.6 – 1.7 倍；但它只占一次乘法的 ≤1.3%，到最大尺寸更是只剩 9% 的余量 ⇒ 端到端 0.1 – 0.4%，在测量噪声里 |
| `load()` / `save()` | 空心孪生显示已经是**访存受限**（离纯拷贝只差 3 – 10%），天花板 0.1 – 0.3% |
| `nat_asmNttMul`（逐点乘） | 两个操作数都是"活值"，没有预存倒数可用；唯一出路是改用 2×52 位表示，而那会让访存翻倍 |
| `nat_asmCRT()`（三模数合并） | 它的 11 条乘法**全部**是"活值 × 常数"，理论上最适合向量化，空心孪生也给了 2.5 – 3.7% 的上限；但我们真的写了一个草稿：**八宽之后算术只快 1.3 – 1.4 倍，而把进位链留在标量会让整体反而慢 1.5 倍**。真做需要再用向量做进位前缀，收益约 1% ⇒ 量过就停 |

## 六、代价

- **需要 AVX-512 硬件**（F/BW/DQ/VL/IFMA 五项）。没有就自动回退到标量内核，结果逐位相同、
  不报错——只是拿不到这份加速。
- **其他一切不变**：内存占用、算法结构、对外接口、结果都与标量版一致。这是这个变体最舒服的
  地方——它是一次纯"换内核"的改动。

---

## 七、这些数字是怎么来的（可信度）

1. **全程整数运算，没有浮点误差**；每个尺寸的结果都与标量内核**逐位比对**，包括每个 D/N、
   每个 chunk 尺寸、每个偏移、三个质数。
2. **同一台机器、同一个 CPU 核、同一个进程内、逐轮交替**（我们、标量、我们、标量……，
   每轮交换先后），取多轮最小值。作为噪声底，我们跑了一个"同一份代码对同一份代码"的
   对照（null），比值在 **0.998 – 1.007** 之间——这正是判读 1 – 2% 差异的标尺。
3. **插电测量**：笔记本用电池时 CPU 频率只有 2.6 – 2.9 GHz，插电后 4.4 – 4.6 GHz，所有
   数字都取自插电状态。
4. **验证规模**：自检套件 **3857 项，0 失败**；另外有一个独立的差分探针（不依赖套件代码）
   把六个内核与标量内核逐位对拍，覆盖 2¹² – 2¹⁶ 的全部内核形状、全部 chunk 尺寸和偏移，
   **95172 例，0 失败**。把 CPU 检测强制关掉、整条走标量路径的构建同样全过。

## 八、后续

这一版可以认为**到头了**：变换已经全部向量化，剩下阶段的余量都用空心孪生和草稿量过，都在
1% 以内或整体为负。真要再往前，只有两条路，都属于"换东西"而不是"优化"：

1. **换数据表示**（2×52 位）：可以让逐点乘也向量化，代价是访存翻倍——需要先算清账。
2. **多线程**：目前是单线程设计，和 GMP 的对比也是单线程口径。

## 附：术语表

| 术语 | 一句话解释 |
|---|---|
| **字（limb）** | 大整数的一个 64 位单元 |
| **变换（NTT）** | 快速傅里叶变换的整数版本，在质数域上做，没有浮点误差 |
| **AVX-512 / zmm** | x86 的 512 位向量指令集 / 它的 512 位寄存器（一条指令算 8 个 64 位数） |
| **IFMA** | AVX-512 的"52 位乘法累加"指令，本版靠它绕开"没有 64×64→128"的限制 |
| **S56** | 项目里的模乘序列：IFMA 估商 + 利用质数 `m = a·2⁵⁶+1` 的形状做修正 |
| **Shoup 法** | 把大部分工作事先算好存表、运行时最省的模乘做法 |
| **lane（道）** | 一个向量寄存器里并排的 8 个 64 位槽位 |
| **蝶形 / 基本运算单元** | 变换的基本运算，一次处理两个数据点 |
| **quarter / 4D 宏块** | 变换里一次处理 4 个数据点的分组方式；一个宏块含四个 quarter |
| **radix-2 / radix-4** | 变换的两种做法：radix-4 把两层合成一遍做，访存量减半 |
| **尾巴（tail）** | 最细一层固定的 (2,1) 对；因为 4D 块这时只有 8 个元素，需要专门内核 |
| **逐位相同** | 每一个 64 位结果都完全一致，不是"误差范围内" |
| **空心孪生 / 真空内核** | 保留访存、删掉算术的对照内核，用来测"算术免费时的上限" |
| **访存 / 执行端口** | 处理器访问内存（含缓存）/ 真正干活的几个发射口，某类指令只能走固定的口 |
